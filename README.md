# BAD READING CLUB

Книжный клуб на React, Vite, TypeScript и Supabase. Публичная часть доступна без аккаунта; организаторы редактируют данные через `/admin`.

## Локальный запуск

Нужен Node.js 22. Скопируйте `.env.example` в `.env`, укажите URL проекта и **publishable/anon key** Supabase, затем выполните:

```sh
npm install
npm run dev
npm run typecheck
npm test
npm run build
```

Не используйте `service_role` или секретные ключи в браузере и не добавляйте `.env` в Git. Без настроенных ключей автоматически включается деморежим: примерные книги и встреча отображаются на сайте, а изменения сохраняются в localStorage этого браузера. Для входа в демоадминку подойдут любые непустые email и пароль. Для сброса демоданных удалите ключ `bad-reading-club-demo-v1` из localStorage браузера. При наличии обоих параметров Supabase используется настоящая база; `VITE_DEMO_MODE=true` принудительно включает деморежим. Демо не обеспечивает авторизацию или защиту данных и предназначено только для локального просмотра.

## Аккаунты участников

Для входа по токену и просмотра профиля нужны MySQL и PHP 8.1 или новее с расширением `pdo_mysql`.

1. Создайте в MySQL отдельную базу `bad_reading_club` с кодировкой `utf8mb4` и пользователя с правами чтения и изменения данных этой базы. Выполните для неё файл `backend/schema.sql`, например:

   ```sh
   mysql -u root -p bad_reading_club < backend/schema.sql
   ```

   В PowerShell оператор `<` не поддерживается; используйте вместо этого команду `source backend/schema.sql` внутри клиента MySQL после выбора базы командой `USE bad_reading_club;`.
2. Скопируйте `backend/config.example.php` в `backend/config.php` и укажите параметры подключения MySQL. Создайте случайный ключ администратора командой `php -r "echo bin2hex(random_bytes(32));"`, сохраните его в надёжном месте и укажите SHA-256 от него в `admin_key_hash` (вычислить можно командой `php -r "echo hash('sha256', trim(fgets(STDIN)));"`, введя ключ). Файл настроек не добавляется в Git и должен оставаться вне публичной директории веб-сервера.
3. В отдельном терминале из корня проекта запустите:

```sh
php -S 127.0.0.1:8000 -t backend/public
```

В другом терминале запустите `npm run dev` и откройте «Мой аккаунт» в меню сайта. Vite перенаправляет запросы `/api` на PHP-сервер; после изменения настроек Vite его нужно перезапустить. Участник входит по персональному токену, в MySQL хранится его хеш. Выдача токенов через интерфейс админки отключена; серверный обработчик сохранён. Для локальной установки проекта ключ администратора сохранён в `.local/admin-key.txt`. Доступ участников независим от входа организатора в Supabase.

Если база была создана до перехода на токены, повторно выполните `backend/schema.sql`: недостающая таблица участников будет добавлена. Прежняя таблица аккаунтов не удаляется автоматически, но вход по email и паролю больше не поддерживается.

Для существующей базы, созданной до появления конструктора аватарок, один раз выполните `backend/002_member_avatar.sql`. В новых базах поле уже создаётся через `backend/schema.sql`. Имя и настройки аватарки сохраняются в профиле участника.

Если PHP и MySQL установлены локально в `.local` для этого проекта, после перезагрузки компьютера их можно запустить в двух отдельных окнах PowerShell из корня проекта:

```powershell
.local/mysql-package/mysql-8.4.13.1-winx64/bin/mysqld.exe --no-defaults --basedir=C:/projects/Bad-Reading-Club/.local/mysql-package/mysql-8.4.13.1-winx64 --datadir=C:/projects/Bad-Reading-Club/.local/mysql-data --bind-address=127.0.0.1 --port=3306 --mysqlx=OFF --console
```

```powershell
.local/php/php.exe -S 127.0.0.1:8000 -t backend/public
```

Данные MySQL и локальные учётные данные находятся в `.local`, которая исключена из Git. Не удаляйте эту папку, пока нужны локальные аккаунты.

Это настройка для локальной разработки: GitHub Pages не запускает PHP, а для размещения в интернете потребуются PHP-хостинг, HTTPS, настройка маршрута `/api` и защита настроек. Выдача токенов защищена отдельным ключом администратора, который нельзя передавать участникам.

## Supabase

1. Создайте проект Supabase. В SQL Editor выполните `supabase/migration.sql`, затем `supabase/002_book_meetings.sql` и `supabase/003_meeting_price.sql`, `supabase/004_remove_reviews_and_ratings.sql` и `supabase/005_save_meeting_with_book.sql` и `supabase/006_remove_book_status.sql` и `supabase/007_meeting_2gis.sql` и `supabase/008_meeting_place.sql` и `supabase/009_book_covers.sql` по одному разу. Если предыдущие миграции уже применены, выполните только недостающие. Миграция создаёт таблицы, RLS, приватный bucket `club-media`, политики Storage и единственную начальную книгу «К востоку от Эдема». Даты и адреса не выдуманы.
2. В Authentication отключите публичную регистрацию (Allow new users to sign up), затем создайте пользователя администратора через панель Authentication → Users → Add user, задав email и пароль. Подтвердите email при создании. В SQL Editor вручную назначьте администратора, подставив UUID из списка пользователей:

```sql
insert into public.admin_users (user_id) values ('UUID-ПОЛЬЗОВАТЕЛЯ');
```

Первого администратора можно назначить только через доверенный доступ к проекту, обычный пользователь не может назначить себя. Повторите для других организаторов. Удаление строки отзывает доступ. Не делайте эти операции из клиентского приложения.
3. Скопируйте Project URL и publishable (или legacy anon) key в `.env`. Перезапустите Vite. Войдите в `/admin` (для project pages добавьте перед ним имя репозитория) указанными email и паролем. Создайте встречу и укажите данные книги в той же форме. При необходимости добавьте ссылку на место в 2ГИС. Сохранённая встреча появится в неопубликованных: нажмите «Опубликовать» рядом с ней и подтвердите публикацию. При удалении последней встречи удаляется и связанная книга.
4. При использовании ограничений доступа к API проверьте, что клиентам разрешены Data API и Storage. Bucket приватный: публичный доступ к обложке разрешается при ссылке на опубликованную книгу. Ранее загруженные фотографии и их политики доступа сохранены в Supabase; приложение больше их не показывает. На странице создаются временные ссылки; уже выданная ссылка работает до окончания срока (один час), даже если запись скрыта. Файлы автоматически уменьшаются в браузере и сохраняются в WebP. При удалении записи приложение удаляет связанные файлы; если сеть прервётся между удалением записи и файла, проверьте bucket на оставшиеся файлы вручную.

## GitHub Pages

В настройках репозитория в Settings → Pages выберите Source: GitHub Actions. Добавьте repository variables `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` и `VITE_BASE_PATH`. Для project pages значение последней — `/Bad-Reading-Club/` (или `/имя-репозитория/`); для custom domain или user pages — `/`. Workflow `.github/workflows/deploy.yml` собирает и публикует ветку `main`. Используется BrowserRouter; для прямых переходов и обновления страниц GitHub Pages возвращает `404.html`, который восстанавливает исходный адрес через корень сайта. Существующие ссылки с `#/` автоматически преобразуются в новые. После настройки и ручной отправки ветки workflow выполнится автоматически; организатору для работы с контентом GitHub не нужен.

## Проверка перед запуском

Откройте сайт из российских сетей без VPN и проверьте доступ как к Pages, так и к API и Storage Supabase. Проверьте анонимный просмотр и попытку записи без авторизации; затем войдите администратором, создайте встречу с книгой, отредактируйте её, опубликуйте встречу и удалите тестовые данные. RLS и Storage должны отклонять запись анонимного пользователя и пользователя без роли. Эти проверки требуют собственного Supabase-проекта и не заменяются одной локальной сборкой.

Supabase Free может приостанавливать неактивные проекты; доступность из РФ, тарифы и бесплатные лимиты могут меняться. Убедитесь, что проект соответствует актуальным условиям сервиса и потреблению клуба.

Внимание: миграция `004_remove_reviews_and_ratings.sql` безвозвратно удаляет ранее сохранённые отзывы и оценки. Перед применением сохраните резервную копию, если эти данные могут понадобиться.

Миграция `008_meeting_place.sql` заменяет место и ссылку у всех существующих встреч на «Ресторан Премьера» и указанный адрес 2ГИС, включая черновики. Для новых встреч место можно указать отдельно.

Обложки книг из списка сохранены в `public/book-covers`; сведения об источниках — в `public/book-covers/sources.json`. Миграция `009_book_covers.sql` подключает эти изображения к книгам с совпадающими названием и автором, только если у книги ещё нет обложки. Собственные обложки не заменяются.
